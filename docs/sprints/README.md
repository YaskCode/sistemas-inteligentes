## Flujo común

1. La profesora define el objetivo y los criterios mediante GitHub Project e Issues.
2. El equipo trabaja en una rama de su repositorio.
3. Las decisiones, pruebas y evidencias se documentan.
4. El equipo abre un Pull Request.
5. La profesora revisa, retroalimenta y aprueba.
6. El cierre del Issue requiere evidencias verificables.

Los sprints se desarrollan en **computing-laboratory**, no en este repositorio.
